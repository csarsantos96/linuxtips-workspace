Imagine que você acabou de provisionar um novo disco em um servidor Linux e precisa que o sistema operacional o reconheça e o torne utilizável para armazenar dados. Quais seriam os passos essenciais que você tomaria para preparar esse disco recém-adicionado para ser montado em um ponto específico do sistema de arquivos?

### Resposta do aluno

Eu seguiria estes passos essenciais:
1. Identificar o novo disco:
lsblk
sudo fdisk -l

2. Criar uma partição, se necessário:
sudo fdisk /dev/nvme1n1

3. Formatar a partição com um sistema de arquivos, como ext4:
sudo mkfs.ext4 /dev/nvme1n1p1

4. Criar o ponto de montagem:
sudo mkdir -p /srv/uploads

5. Montar o disco:
sudo mount /dev/nvme1n1p1 /srv/uploads

6. Conferir:
df -h /srv/uploads

Para manter a montagem após reinicializações, eu usaria o UUID obtido com blkid no /etc/fstab, adicionando opções como nofail:
UUID=<uuid-do-disco> /srv/uploads ext4 defaults,nofail 0 2

Depois, testaria a configuração:
sudo mount -a

Você tem um diretório `/data` que está crescendo muito rápido e você precisa monitorar o espaço em disco que ele está consumindo, mas quer uma visão mais detalhada do que apenas o total. Qual comando você usaria para listar o espaço ocupado por cada subdiretório dentro de `/data`, ordenado do maior para o menor, para identificar rapidamente quais subdiretórios estão consumindo mais espaço?

### Resposta do aluno

Eu usaria:
sudo du -h --max-depth=1 /data | sort -hr

- du -h: exibe os tamanhos em formato legível;
- --max-depth=1: mostra o total de /data e seus subdiretórios imediatos;
- sort -hr: ordena do maior para o menor.
Se eu quisesse listar apenas os subdiretórios, poderia usar:
sudo du -sh /data/* | sort -hr

Vamos para a última pergunta, então.

Em um ambiente onde a integridade dos dados é crucial, você precisa garantir que um volume persistente em um contêiner Docker, que está montado em `/app/data`, não seja perdido caso o contêiner seja removido acidentalmente. Qual é a principal característica de um volume Docker que o diferencia de um bind mount comum nesse cenário de persistência de dados?

### Resposta do aluno

A principal diferença é que um volume Docker é gerenciado pelo próprio Docker e fica armazenado fora do ciclo de vida do contêiner, normalmente em /var/lib/docker/volumes.
Assim, mesmo que o contêiner seja removido, os dados permanecem no volume, desde que ele não seja removido explicitamente:
docker rm meu-container

Para remover o volume também, seria necessário fazer isso de forma explícita:
docker volume rm meu-volume

Exemplo de uso:
docker run -d \
  --name minha-app \
  -v dados-app:/app/data \
  minha-imagem

Um bind mount, por outro lado, aponta diretamente para um diretório específico do host. Ele também pode persistir os dados, mas depende da existência, permissões e gerenciamento manual desse diretório.
