Imagine que você tem dois containers Docker, um rodando um servidor web e outro rodando um banco de dados. Como você faria para que o container do servidor web pudesse se comunicar com o container do banco de dados usando um nome de host em vez de um endereço IP?

### Resposta do aluno

Eu criaria uma rede Docker personalizada e conectaria os dois containers a ela:
docker network create minha-rede

docker run -d \
  --name banco \
  --network minha-rede \
  postgres:16

docker run -d \
  --name web \
  --network minha-rede \
  minha-imagem-web

Dentro do container web, eu usaria o nome do container como hostname:
DB_HOST=banco

Em uma rede Docker criada pelo usuário, o DNS interno resolve automaticamente banco para o IP do container, sem precisar descobrir ou fixar o endereço IP.

Para fechar, vamos pensar no seguinte cenário: você tem um container que está rodando um serviço e você quer que ele possa acessar a internet para baixar atualizações, por exemplo. Por padrão, os containers já têm acesso à rede externa, certo? Mas se você quisesse *restringir* o acesso de um container específico a apenas um IP e porta de destino específicos na internet, como você faria isso?

### Resposta do aluno

Eu faria essa restrição usando regras de firewall no host Docker, com iptables ou nftables, filtrando:
- o IP de origem do container;
- o IP de destino permitido;
- a porta permitida;
- bloqueando o restante do tráfego de saída.
O Docker não possui uma flag simples do docker run para limitar a saída a um único IP e porta. Em ambientes mais complexos, também poderia usar um plugin de rede ou um proxy de saída.
Exemplo conceitual:
# Permitir apenas o destino 203.0.113.10 na porta 443
sudo iptables -A DOCKER-USER -s <IP_DO_CONTAINER> \
  -d 203.0.113.10 -p tcp --dport 443 -j ACCEPT

# Bloquear os demais acessos externos
sudo iptables -A DOCKER-USER -s <IP_DO_CONTAINER> -j DROP

A cadeia DOCKER-USER é apropriada porque permite aplicar regras personalizadas antes das regras de encaminhamento do Docker.
