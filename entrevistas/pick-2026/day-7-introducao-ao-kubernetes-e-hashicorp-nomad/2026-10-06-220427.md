Agora, pensa no seguinte cenário: você tem um conjunto de Pods que precisam ser executados apenas uma vez e, após a conclusão, não devem ser reiniciados automaticamente. Qual recurso do Kubernetes você utilizaria para gerenciar isso?

### Resposta do aluno

Eu utilizaria um Job do Kubernetes.
O Job executa uma tarefa até sua conclusão bem-sucedida e, depois disso, não cria novos Pods. Para evitar reinicializações em caso de falha, poderia configurar:
apiVersion: batch/v1
kind: Job
metadata:
  name: tarefa-unica
spec:
  backoffLimit: 0
  template:
    spec:
      restartPolicy: Never
      containers:
        - name: tarefa
          image: minha-imagem:1.0
          command: ["sh", "-c", "echo Tarefa concluída"]

Assim, o Pod roda uma vez e termina. Para tarefas que precisam ser executadas periodicamente, eu usaria um CronJob.

Como você instruiria o Nomad a garantir que essa aplicação seja agendada apenas em nós que atendam a esses requisitos?

### Resposta do aluno

No Nomad, eu definiria os requisitos dentro do bloco resources da tarefa:
job "minha-aplicacao" {
  datacenters = ["dc1"]

  group "app" {
    task "web" {
      driver = "docker"

      config {
        image = "minha-aplicacao:1.0"
      }

      resources {
        cpu    = 1000 # MHz
        memory = 2048 # MB
      }
    }
  }
}

O Nomad só agenda a aplicação em nós que tenham pelo menos 1000 MHz de CPU e 2048 MB de memória disponíveis. Se também fosse necessário exigir características específicas do nó, eu combinaria isso com constraint, usando atributos ou metadados do cliente.
