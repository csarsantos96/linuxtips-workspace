Imagina que você precisa rodar um aplicativo web simples que consiste em um frontend em Node.js e um banco de dados PostgreSQL. Como você usaria o Docker Compose para definir e subir esses dois serviços em conjunto, garantindo que eles possam se comunicar?

### Resposta do aluno

Eu criaria um arquivo compose.yaml definindo os serviços frontend e db na mesma rede padrão do Compose:
services:
  frontend:
    build: .
    ports:
      - "3000:3000"
    environment:
      DATABASE_URL: postgresql://app:senha@db:5432/appdb
    depends_on:
      - db

  db:
    image: postgres:16
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: senha
      POSTGRES_DB: appdb
    volumes:
      - postgres_data:/var/lib/postgresql/data

volumes:
  postgres_data:

Depois, subiria os serviços com:
docker compose up -d

O Compose cria uma rede para a aplicação. Por isso, o frontend acessa o PostgreSQL usando db como hostname e a porta interna 5432, sem precisar usar o IP do container. O volume garante a persistência dos dados do banco.

Para fechar, vamos pensar em um cenário um pouco diferente. Suponha que você está desenvolvendo uma aplicação e precisa testar diferentes configurações de ambiente para um serviço, como mudar a porta exposta ou variáveis de ambiente, sem ter que alterar o arquivo `docker-compose.yaml` principal toda hora. Como você faria isso de forma organizada?

### Resposta do aluno

Eu usaria um arquivo de override, como compose.override.yaml, ou arquivos específicos por ambiente, como compose.dev.yaml e compose.test.yaml.

Exemplo:

# compose.dev.yaml
services:
  frontend:
    ports:
      - "8080:3000"
    environment:
      NODE_ENV: development
      API_URL: http://localhost:9000

Para subir essa configuração junto ao arquivo principal:

docker compose -f compose.yaml -f compose.dev.yaml up -d

O segundo arquivo sobrescreve ou complementa as configurações do primeiro, mantendo o arquivo principal limpo e permitindo testar diferentes ambientes de forma organizada.
