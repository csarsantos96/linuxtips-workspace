Para nossa última pergunta, vamos falar sobre como o Docker gerencia o armazenamento e otimiza o uso de espaço. O conceito de **Copy-On-Write (COW)** é essencial para isso.

Em termos práticos, como o Copy-On-Write beneficia a criação e o uso de múltiplos containers baseados na mesma imagem?

### Resposta do aluno

O COPY-ON-WRITE(COW) permite multiplos containers baseados na mesma imagem compartilhem as mesmas camadas(layers) da imagem en disco, sem duplica-las. A imagem é composta por camadas read-only(somente leitura), e todos os containers apontam para essas mesmas camadas

Quando você sobe vários containers da mesma imagem, o Docker não copia a imagem inteira para cada um. Todos compartilham as camadas read-only da imagem

Cada container recebe apenas uma fina camada gravável (writable layer) no topo, própria dele. 
Enquanto o container só lê um arquivo, ele lê direto da camada compartilhada da imagem. A cópia só acontece no momento em que ele precisa escrever/modificar aquele arquivo — aí o arquivo é copiado para a camada gravável do container e a alteração fica isolada ali. Daí o nome "copiar ao escrever".

Os benefícios práticos:

Economia de disco: dez containers da mesma imagem não ocupam dez vezes o tamanho da imagem — a imagem existe uma vez, e cada container só adiciona o que efetivamente modificou.
Velocidade na criação: subir um container é quase instantâneo, porque não há cópia da imagem inteira — só se cria a camada gravável vazia por cima.
Isolamento: as alterações que um container faz ficam na camada dele e não afetam a imagem original nem os outros containers.
Uso eficiente de memória/cache: como as camadas base são as mesmas, o SO pode inclusive compartilhar cache de leitura entre containers.
